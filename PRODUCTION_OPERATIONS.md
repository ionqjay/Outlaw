## Local deadline implementation — 2026-10-30 (NOT deployed)
The earlier30s warning describes the currently deployed release, not this new local revision. The readiness helper now resolves false at a3,000ms application timer and aborts the shared probe signal; HTTP health maps false to503 with the same response contract. Five-second success/failure cache remains. Config is checked after dependency await and on every response, including cache hits. Timer scheduling cannot guarantee wall-clock delivery during event-loop stalls, Render cold start, network/proxy delay or process failure. No uptime SLA implied.

Single-flight ownership survives a timeout until underlying work settles: callers immediately get false rather than accumulating duplicate probes, even after TTL. Late success cannot overwrite timeout failure. SQL dependency groups use allSettled so one rejection cannot release ownership while sibling reads are still running; aborted work cannot advance to the next group. REST reads combine the shared signal with the existing10s I/O limit. Readiness-only private-bucket metadata GET uses the same Storage endpoint as getBucket with the shared signal (SDK getBucket has no per-call signal); ordinary object operations are unchanged. No new dependencies or runtime configuration. A truly noncooperative never-settling dependency stays fail-closed until process restart; cancellation-capable fetch permits normal recovery after failure TTL.
